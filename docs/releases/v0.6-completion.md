# Version 0.6 completion report

Completed and verified on 23 July 2026.

## Features implemented

- Optional Ollama and LM Studio support in the standalone desktop app.
- Local provider selection, editable loopback endpoint, connection test,
  installed-model discovery, model selection, 1–120 second request timeout, and
  1–10 tool-loop controls.
- Natural-language conversations using the same 48 trusted companion tools as
  MCP.
- Multi-turn, multiple sequential, and same-turn parallel tool calls.
- In-memory conversation state, profile-aware local context, manual reset, and
  visible running/succeeded/failed tool activity.
- Complete No-AI mode retained as the default.
- Optional live provider smoke commands and end-user setup guidance.

## Architecture changes

- Added the independent `@gielinor/agent-runtime` workspace.
- Moved all MCP input schemas and the generic result envelope into
  `@gielinor/shared-types`.
- Added a shared 48-tool registry that produces model function schemas from the
  same Zod inputs used by MCP.
- Added normalized Ollama and LM Studio adapters over an injected bounded JSON
  transport.
- Added Tauri's Rust-backed HTTP plugin with a loopback-only URL scope. Local
  model requests do not depend on webview CORS settings.
- Kept calculations and RuneScape data behavior in existing core services and
  tool execution behind the desktop MCP bridge.

## Database migrations

None. Version 0.6 does not change the SQLite schema, profile export version, or
retained Version 0.1–0.5 records.

## MCP tools added or changed

No tool names or semantic contracts changed. The existing 48 input schemas now
come from the shared package so MCP and model-provider schemas cannot drift.

## Tests added

- 16 agent-runtime tests covering shared schema generation, provider adapters,
  endpoint restrictions, single/sequential/parallel calls, invalid arguments,
  unknown names, loop limits, timeouts, model/provider unavailability, partial
  responses, malformed JSON, invalid outputs, tool failures, and conversation
  state.
- 4 React tests covering Ollama conversation, provider failure, remote-endpoint
  rejection, and corrupt stored setting repair.
- 3 Playwright journeys covering Ollama, LM Studio, tool activity, conversation
  reset, and local-provider failure.
- Existing MCP, core, provider, database, desktop, and native bridge tests remain
  unchanged and green.

## External APIs used

- Ollama `GET /api/tags`, `POST /api/show`, and `POST /api/chat`.
- LM Studio OpenAI-compatible `GET /v1/models` and
  `POST /v1/chat/completions`.
- Existing Jagex and RuneScape Wiki providers are unchanged.

No model-provider credentials or cloud endpoints are used.

## Known limitations

- A separately installed and running provider plus a tool-capable local model is
  required for AI conversations.
- LM Studio's OpenAI-compatible model list does not consistently expose a
  machine-readable tool-capability flag; unsupported selections fail clearly.
- Loopback provider authentication, LAN servers, and cloud model endpoints are
  not supported.
- Conversation history is intentionally not persisted.
- A model's prose may still be incomplete; only validated tool activity is
  confirmed companion data.
- Desktop development installers remain unsigned and unnotarized.

## Security considerations

- Endpoint parsing and native Tauri ACLs independently reject non-loopback
  model traffic.
- Redirects, embedded credentials, query strings, cloud keys, arbitrary shell
  calls, and generic network permissions are absent.
- Provider request, response, tool-result, per-turn call, timeout, history, and
  loop bounds limit resource use.
- Every model-requested name and input is validated before execution; every
  result is validated and source-stamped before entering the model context.
- Failed calls remain explicit error messages and never become successful
  trusted-tool activity.
- Gameplay remains read-only: no input simulation, client memory, packets,
  trading, CAPTCHA handling, credentials, or anti-cheat bypass.
