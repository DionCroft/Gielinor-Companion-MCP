## Runtime and distribution

Native production uses only the supported Tauri bridge, bundled local MCP
runtime, and SQLite. The single-instance plugin is registered first; a second
launch focuses the existing window and shows an already-running notice. Missing
or corrupt runtime components produce actionable native errors and never select
preview data.

Windows release names are:

- `Gielinor-Companion-Setup-1.2.0-x64.exe` (recommended NSIS);
- `Gielinor-Companion-1.2.0-x64.msi` (managed deployment);
- `Gielinor-Companion-Portable-1.2.0-x64.zip` (explicit isolated mode).

The same tag emits architecture-labelled macOS DMG, Linux AppImage/DEB, SHA-256
checksums, SPDX SBOM, release notes, and GitHub attestations. Installed mode is
per-user and portable mode activates only with `--portable`; their database and
runtime paths never mix. The source launcher validates package version,
Node.js 22/24, Corepack, Rust, and lockfile state, writes diagnostic logs, and
launches native-real only.

## Provenance and production boundary

The shared `DataOrigin` contract is `live-public`, `validated-cache`,
`manual-local`, `imported-local`, `alt1-confirmed`, `derived`,
`preview-fixture`, or `unavailable`. Every MCP response supplies provenance and
the desktop inherits it through Live, Cached, Manual, Imported, Alt1 confirmed,
Calculated, Preview, and Unavailable badges. Provider/source, timestamp,
freshness, cache state, confidence, warnings, and trace IDs are retained where
applicable.

The production entry imports `native-bridge.ts`; preview/test code is loaded
only by an explicit preview-enabled build and explicit query mode. The emitted
production graph verifier rejects demo bridges/profiles, browser fixture
catalogues, screenshot fixtures, and deterministic fake market markers. Preview
keeps a persistent warning on every page.

## Live providers and feature ownership

- Jagex Hiscores: normal, Ironman, Hardcore Ironman, total values, ranks, and
  all 29 supported skills.
- RuneScape Wiki: revision-aware quest definitions and sourced training
  methods with coverage/warnings and last-valid-snapshot retention.
- RuneScape Wiki/Weird Gloop: RS3 item catalogue, guide values, buy limits,
  supported values/volume, and timestamps.
- Jagex ItemDB/graph: on-demand current guide value and up to 180 daily points.
- Weird Gloop history/news: independent RS3 history/volume and exact validated
  event context with provider disagreement.
- GitHub Releases: read-only stable update metadata, recommended platform
  asset, release notes, and checksum-metadata availability.

Guide values/history are not a live order book or guaranteed fill. Market
scores and manual zones remain deterministic; local language models can explain
but cannot calculate them or place offers.

Public providers do not expose a complete bank, inventory, equipment, cash
pouch, active offers, exact completed transactions, acquisition cost, complete
quest state, or current location. These remain manual, imported,
Alt1-confirmed, or Unavailable. The RuneMetrics quest endpoint was live-audited
but not adopted because it is undocumented, varies with privacy/session state,
and is not a reliable supported contract. Local confirmation remains
authoritative.

## Desktop changes

First run has eleven visible stages from runtime/database readiness through
profile creation, Hiscores, three catalogues, history, market readiness,
provenance verification, and completion. Optional failures retain valid data,
support retry, and require an explicit limited-mode continuation.

The dedicated Data Sources view reports provider, capability, success/failure
times, circuit, cache age, next refresh, record count, validation coverage,
origin, and warning/error. Its bounded **Verify live data now** action refreshes
only public snapshots. Redacted export excludes player-private records.

Profiles, skills, quest planning, levelling, market analysis, holdings,
journals, watchlists, paper trading, backtests, update status, and source status
inherit provenance. Imported/manual records retain their origin. Optional Alt1
capture remains opt-in, read-only, review-first, confidence-labelled, and never
modifies state without confirmation.

## Compatibility and safety

All 93 Version 1.1 MCP tools remain in the same order with the frozen 48-tool
Version 1.0 prefix. Profile export v1, provider plugin API v1, and SQLite schema
8 are unchanged. Ordinary install/upgrade/uninstall preserves existing local
data. No mouse/keyboard generation, gameplay automation, GE offer placement,
credential handling, client-memory access, packet interception, or CAPTCHA
handling exists.

## Known limitations and Version 1.3

- Platform signing/notarization requires maintainer-owned certificates.
- Exact public quest completion has no adopted reliable supported provider.
- Public RS3 price feeds do not expose an order book or guaranteed execution.
- Alt1 visible-interface extraction is necessarily partial and confirmation
  gated; unreliable OCR is deferred rather than guessed.
- Local Windows Installer Service prevented a normal local ICE-validated MSI;
  hosted Windows release validation is mandatory.

Version 1.3 should prioritise independently exercised installer/signing
matrices, a signed rollback-capable updater, and any future official Jagex
plugin/API contract that can improve account-aware imports without credentials,
memory access, or automation.
