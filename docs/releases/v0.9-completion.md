# Version 0.9 completion record

Date: 2026-07-24

## Outcome

Version 0.9 makes data providers independently extensible and adds the migration,
offline, resilience, performance, security, accessibility, and contributor
contracts required for long-term maintenance. Existing MCP tools, profile
exports, deterministic calculations, desktop behavior, hosted isolation, local
AI, and the optional overlay remain backward compatible.

## Features implemented

- Typed provider plugins for six capabilities with source/version metadata,
  integer priority, offline support, and descriptions.
- Shared result validation, deterministic fallback, preserved disagreement
  records, atomic registration, and per-capability health.
- Default Jagex/Wiki plugin factory behind the unchanged core provider ports.
- Cache-only headless offline routing with retained expired data and stable
  cache-miss/capability errors.
- URL- and cache-key in-flight request deduplication.
- Named/ordered SQLite migration planning and transactional application.
- Generic copied data migrations and legacy profile version 0 to version 1.
- Operational query indexes, configurable SQLite busy timeout, profiler, and
  hosted load driver.
- Threat model, security/dependency/accessibility audits, contributor guides,
  provider issue form, and pull request checklist.
- RustSec and Node dependency audit jobs in CI.

## Architecture changes

Application composition roots now create `ProviderRegistry` and pass
`ProviderPortAdapter` to existing core services. Adding a provider changes only
the composition root and provider package. The registry owns routing evidence;
the core still owns calculations and persistence rules.

`VersionedDataMigrator` and the exported database migration runner make version
edges executable and testable. Neither tool mutates source data on failure.

## Database migrations

Schema version 5 adds indexes for profile update time, provider cache expiry,
quest/training check time, GE retrieval time, and cross-item history timestamp.
The migration is additive. A version-4 upgrade and injected failing version-6
migration prove planning, application, and rollback.

## MCP tools added or changed

No tool was added, renamed, or removed. The 48-name V0.9 contract snapshot
passes. `import_player_profile` additionally accepts the documented legacy
version-0 migration fixture while export remains strict version 1.

## Tests added

Twenty-three deterministic repository tests and one desktop accessibility test
cover:

- provider priority, fallback, malformed results, disagreement, health,
  offline eligibility, and atomic registration;
- concurrent HTTP/cache refreshes and failed cache-lock recovery;
- cache-only expired-data reads and offline misses;
- schema compatibility, profile/data migration, migration rollback, and future
  version rejection;
- database locks and operational indexes;
- 2,000 profiles, a 1,000-node quest graph, memory bounds, and hosted load;
- desktop landmarks, skip navigation, current-page state, and accessible button
  names.

## External APIs used

No new RuneScape data API is introduced. Built-in Jagex and RuneScape Wiki
adapters retain their V0.8 contracts. Dependency review uses the npm advisory
service and RustSec advisory database.

## Known limitations

- Plugin registration is code-based; unsigned dynamic package discovery is not
  enabled.
- Provider health is in-memory and resets with the process.
- Offline mode is an application routing policy, not an operating-system
  firewall.
- Load/performance budgets are regression tests, not deployment capacity
  guarantees.
- RustSec runs in CI because `cargo-audit` was not installed locally.
- Desktop release artifacts remain unsigned until operator signing credentials
  are available.

## Security considerations

- Plugin results cannot bypass shared runtime validation.
- Invalid providers fall back without merging partial data.
- Original migration inputs and prior database schemas survive injected failure.
- No new capability can access credentials, local files, models, MCP tools, or
  RuneScape gameplay through the provider interface.
- The transitive Hono adapter is locked to patched version 2.0.11.
- The existing hosted isolation, overlay no-input/network, and local-model
  loopback boundaries remain enforced.
