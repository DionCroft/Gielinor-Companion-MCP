# Version 0.2 completion report

Completed and verified on 23 July 2026.

## Features implemented

- RuneScape Wiki quest provider over the documented Bucket and MediaWiki APIs.
- Revision-aware full-catalogue synchronization with per-quest source revisions,
  source timestamps, canonical links, and SHA-256 content hashes.
- Quest aliases, membership, difficulty, length, skill and quest-point
  requirements, direct prerequisite groups, item requirements, recommended
  items, quest points, experience/unlock/other rewards, and manual checks.
- Completed, in-progress, and not-started profile status with single and bulk
  updates.
- Available-quest filtering and explainable profile-aware ranking.
- Missing prerequisite, skill, quest-point, and manual requirement reporting.
- Prerequisite-first route generation, deep traversal, cycle detection, started
  requirements, and shortest-branch selection for alternative groups.
- Route shopping lists with case-insensitive duplicate aggregation and explicit
  item alternatives.
- Source and synchronization health inspection.
- Reusable `refresh:quests` setup command with a one-time pre-V0.2 SQLite backup
  and profile-integrity report.

## Architecture changes

- Added quest domain/status/snapshot/route/shopping Zod contracts to
  `@gielinor/shared-types`.
- Added `QuestDataProvider` and `QuestRepository` ports plus `QuestService` to
  `@gielinor/core`.
- Added `RuneScapeWikiQuestProvider` to `@gielinor/providers`.
- Added `SqliteQuestRepository` to `@gielinor/database`.
- Composed the same quest service behind stdio MCP; no quest rules live in the
  transport.

## Database migrations

Additive migration 2 creates:

- `quests` for validated domain JSON, hashes, revisions, and timestamps;
- `quest_aliases` for normalized ID/name/alias resolution;
- `quest_sync_status` for last attempt, last success, retained count, revision,
  and safe failure metadata.

Migration 1 profile and provider-cache tables are untouched. Version 0.1 profile
JSON and export schema version 1 remain compatible.

## External APIs used

- RuneScape Wiki `action=bucket` for `quest`, `quest_rewards`, and
  `infobox_quest`.
- RuneScape Wiki MediaWiki revisions for quest pages and
  `Module:Questreq/data`.
- Existing Jagex public Hiscores and Grand Exchange ItemDB providers remain
  unchanged.

No credentials or paid API are required.

## Security considerations

- All external rows and final domain objects are runtime-validated.
- Requests use timeouts, bounded retries, and a descriptive User-Agent.
- Empty, malformed, duplicate, alias-ambiguous, and suspiciously truncated
  snapshots are rejected before commit.
- Snapshot writes and alias replacement occur in one SQLite transaction.
- A failed refresh retains prior quest rows and last-success metadata.
- MCP errors expose stable safe codes, not stack traces, response bodies, or
  local paths.
- Profile status changes are companion-local. No gameplay input, client memory,
  packet access, account credentials, or automation exists.

## Known limitations

- Wiki item/reward markup cannot reliably prove consumption or tradeability, so
  those claims are not inferred.
- `Misc:` requirements are surfaced for manual verification.
- Lore/comprehension-only `Full:` and `Follows:` graphs are not mandatory route
  edges.
- Quest status is manual because public Hiscores do not expose a complete,
  trustworthy per-player quest-state feed.
- Refresh is user/operator initiated; scheduling and richer provider health are
  later roadmap work.
