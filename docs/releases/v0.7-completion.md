# Version 0.7 completion record

Date: 2026-07-23

## Outcome

Version 0.7 adds a production-oriented remote MCP boundary without changing the
48 existing tool names or input contracts. Local stdio, desktop no-AI, and local
Ollama/LM Studio paths remain available.

## Delivered

- Standards-compliant stateless Streamable HTTP at `/mcp`, using the official
  TypeScript SDK and one server/transport pair per request.
- Anonymous public-source and deterministic tools.
- Optional bearer-token accounts for private profile tools.
- One SQLite profile file per validated account UUID, plus separate shared
  public data and token-digest control databases.
- Operator-only quest, training, and price refresh tools.
- Account creation gate, complete portable-profile export/import, exclusive
  deletion, token revocation, and exact account-file removal.
- Host and Origin allowlists, forwarded-HTTPS enforcement, fixed content types,
  request/message size caps, separate request/tool-call limits, Node timeouts,
  no-store/browser security headers, and stable public errors.
- Privacy-preserving JSON logs with no tokens, bodies, display names, profile
  content, provider bodies, paths, or stacks.
- Liveness and readiness endpoints with public dataset state.
- Non-root/read-only container, loopback-bound Compose profile, TLS reverse-proxy
  example, production environment template, and container CI job.
- Current deployment, privacy, ChatGPT, Claude/Claude Desktop, and Claude Code
  guidance.

## Interoperability basis

- MCP's current TypeScript SDK recommends Streamable HTTP for remote servers and
  documents stateless request handling:
  <https://ts.sdk.modelcontextprotocol.io/server>.
- The MCP transport specification requires a single Streamable HTTP endpoint and
  Origin validation:
  <https://modelcontextprotocol.io/specification/2025-11-25/basic/transports>.
- ChatGPT custom apps connect to remote MCP servers and currently expose
  plan/workspace-specific developer-mode controls:
  <https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt-beta>.
- Claude documents remote custom connectors, while Claude Code documents both
  Streamable HTTP and fixed Authorization headers:
  <https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp>
  and <https://code.claude.com/docs/en/mcp>.

## Explicit limitations

- Version 0.7 does not implement OAuth. ChatGPT and Claude custom connectors use
  the anonymous public surface; private profiles require a client that can
  configure the bearer header.
- Rate and activity limits are in-memory per service instance. Horizontal
  scaling requires an external gateway/distributed limiter and coordinated
  storage.
- TLS is terminated by the operator's reverse proxy.
- Deletion cannot remove backups or snapshots outside the live data directory.
- Public catalogues begin as `never-synced` until the operator invokes the
  restricted refresh tools.
- No public hosted instance or domain is provisioned by the repository.

These limitations are documented and do not weaken the local-only safety model
or imply any RuneScape gameplay automation.
