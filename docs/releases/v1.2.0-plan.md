# Version 1.2.0 implementation plan and gap analysis

Version 1.2.0 is the one-click launch and live-data completion release. It is
built on the validated Version 1.1.0 baseline at `origin/main` (`4c207fa`) and
must preserve all 93 MCP tools, the frozen 48-tool Version 1.0 prefix, profile
export v1, database schema v8, provider plugin API v1, local-private data, and
the read-only gameplay boundary.

## Baseline evidence

The clean Version 1.1.0 baseline passed `corepack pnpm test:release` on Windows
on 3 August 2026. That gate rebuilt every workspace, verified the safety
boundary, passed the eight stable-contract/upgrade tests, and confirmed the
93/48 tool counts and database/profile/provider versions.

The work is isolated on `agent/v1.2-one-click-live-data`. Unrelated pnpm 11
changes in another checkout are deliberately outside this branch.

## Source-truth contract

Every user-facing result introduced or touched in Version 1.2 will use one of:

- `live-public`;
- `validated-cache`;
- `manual-local`;
- `imported-local`;
- `alt1-confirmed`;
- `derived`;
- `preview-fixture`;
- `unavailable`.

The origin is accompanied, when applicable, by provider/source, observed or
generated timestamp, freshness/cache state, confidence, warnings, and trace ID.
Missing values remain missing; empty provider responses are not converted into
zeros or completion state.

## Vertical implementation slices

1. **Distribution foundation.** Bump release metadata, add single-instance
   behavior, portable data-root resolution, the root launcher, Windows installer
   configuration, portable packaging, asset checks, and focused tests.
2. **Production graph boundary.** Split preview/test fixtures from the native
   bridge and fail the build when native production can reach fixture code.
3. **Universal provenance.** Add backward-compatible origin types and helpers,
   propagate them through status/envelope boundaries, and render consistent
   badges and details.
4. **Live-data completion.** Audit player, quest, training, market, portfolio,
   journal, paper-trading, backtest, news, updates, and status views against the
   source-truth contract; repair real native paths and explicit unavailable
   states.
5. **First-run and diagnostics.** Validate all eleven stages, per-stage retry,
   limited/offline/cache behavior, “verify now”, and redacted provenance output.
6. **Release proof.** Complete installer/upgrade/uninstall/portable smoke tests,
   run the full quality-gate matrix, document artifacts and limitations, and
   publish only after the branch is clean and remote checks pass.

## Buildability rule

Each slice must leave `build`, relevant focused tests, stable contracts, and the
safety boundary passing. Version 1.2.0 is not complete merely because source
changes exist; installer behavior, production fixture unreachability, real-data
labelling, and the required release assets need recorded evidence.
