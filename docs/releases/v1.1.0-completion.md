## Runtime modes

| Mode                       | Behaviour                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `native-real`              | Uses Tauri commands, the bundled/current MCP runtime, and local SQLite. Production cannot instantiate the demo bridge.                                 |
| `browser-live-development` | Clearly reports that standalone browser mode is not connected and directs the developer to `corepack pnpm desktop:dev`. It never substitutes fixtures. |
| `browser-preview`          | Requires explicit selection and permanently displays `Preview data — not connected to RuneScape or your local profile.`                                |
| `automated-test`           | Requires an explicit mode/query flag and uses deterministic fixtures only in tests.                                                                    |

The local stdio server reports `local-stdio-real`, the hosted server reports
`hosted-real`, and native Tauri reports `native-real`. Backend-enforced offline
mode prevents provider calls, retains valid cached data, returns structured
offline failures for live-only operations, and lowers stale-data confidence.

## Real-data providers and source coverage

- Jagex public Hiscores: 29 supported RS3 skills with level, XP, and rank for
  normal, Ironman, and Hardcore Ironman modes. This is a public snapshot, not
  an authenticated account connection.
- RuneScape Wiki quests: revision-aware definitions, aliases, membership,
  difficulty, length, prerequisites, quest points, skill/item requirements,
  rewards, URLs, revision IDs, timestamps, hashes, field warnings, and coverage
  counts. Invalid refreshes do not replace the previous valid snapshot.
- RuneScape Wiki training: revisioned level bands, sourced numeric rates,
  requirements, intensity/AFK evidence, confidence, and uncertainty. Unsourced
  numeric rates are excluded from time estimates.
- RuneScape Wiki/Weird Gloop catalogue: item identity, guide prices, buy limits,
  alchemy/store values, published volume, and update timestamps.
- Jagex ItemDB: backward-compatible item details and current guide values.
- Jagex graph: up to 180 daily guide-price and moving-average observations.
- Weird Gloop exchange history: independent price/volume history and latest
  values. The analyser compares it with Jagex graph data and explicitly reports
  disagreement or uses a labelled fallback.
- RuneScape news: source-backed recent item context only when an exact item
  identity/title match is available. The UI states that correlation does not
  prove causation.

Every public result carries source, retrieval time, cache state, freshness,
warnings, and trace metadata where applicable. Public RS3 GE sources are
guide-price/history feeds, not a live order book or proof of instant execution.

The 11-stage first-run workflow validates SQLite, creates/selects the profile,
refreshes Hiscores, quests, training, and GE data in sequence, validates
coverage, and then opens the dashboard. A stage can be retried or bypassed in
truthfully labelled limited mode without deleting valid data from another
stage.

## Player-private local data and migrations

SQLite schema 7 adds versioned holdings snapshots, cash, average acquisition
costs, trade records, market preferences, watchlists, and the selected-profile
singleton. Schema 8 adds the paper portfolio. Migrations are forward-only,
transactional, backup-aware, and retain Version 1 data.

The desktop and MCP support:

- manual holdings and cash entry;
- confirmed source labels (`manual`, `csv-import`, `json-import`, or
  `alt1-confirmed`);
- CSV/JSON holdings import and export;
- a manual buy/sell journal;
- watchlists and risk/strategy preferences;
- selected-profile-aware planners and optional subtraction of confirmed
  holdings;
- locally confirmed quest progress;
- paper trades and portfolio state.

Public APIs do not expose a complete bank, inventory, equipment set, active GE
offers, or complete quest state. Version 1.1 never claims otherwise. Alt1 is
read-only and only confirmed visible-UI suggestions may alter local state; no
client memory or generated game input is used.

## Market indicators and scoring

`MarketIntelligenceService` is deterministic. It calculates current/previous
guide value; 1/7/30/90/180-day change when enough observations exist; 7/30/90
day simple moving averages; distance from the 30-day average; return
volatility; historical high/low and distance; outlier score; volume and 30-day
average volume; buy limit; freshness; provider agreement; event instability;
holdings; acquisition cost; budget; and allocation fit.

Strategy configuration `1.1.0-strategy-v1` records all thresholds and weights.
Trend and mean-reversion strategies each weight the primary strategy score at
35%, liquidity 15%, volatility/risk 15%, freshness 10%, source confidence 10%,
and user fit 15%. The default thresholds are 78 for strong-buy candidates, 65
for buy candidates, 35 for avoid, 30 minimum history points, 12% extreme daily
volatility, 10% provider disagreement, and 36 hours before freshness decay.

The service stores a 0–100 trend, mean-reversion, liquidity, volatility/risk,
freshness, source-confidence, user-fit, and overall-opportunity component with
an explanation for each. Results are one of:

- `strong-buy-candidate`;
- `buy-candidate`;
- `watch`;
- `hold`;
- `reduce`;
- `sell-candidate`;
- `avoid`;
- `insufficient-data`.

Extreme volatility, insufficient history, low configured liquidity, stale
sources, provider disagreement, and unstable/new-item policy can reject or
downgrade a candidate. A sell candidate requires a recorded holding; unheld
weak items become `avoid` or `watch`.

Manual order-plan quantity is capped by recorded available GP, maximum
allocation percentage, risk multiplier (low 0.5, medium 0.75, high 1), current
guide value, published buy limit, and existing held quantity for reductions.
Entry, profit-taking, and invalidation zones come from guide-price volatility
and are explicitly estimates, not executable quotes. No offer is placed,
edited, or cancelled.

## Portfolio, paper trading, and backtesting

Portfolio calculations cover current guide value, cost basis, manually
realised gain/loss, unrealised guide-value gain/loss, allocation,
concentration, stale exposure, and missing-price exposure. Unrealised results
remain labelled estimates until a trade is recorded.

Paper trading persists separately from real journal data and never interacts
with RuneScape. Backtests use only observations available at each simulated
date, delayed fills, configurable slippage, buy limits, non-overlapping
positions, separate training/evaluation periods, and sequential expanding
walk-forward windows. Reports include signal count, hit rate, mean/median
return, drawdown, volatility, turnover, holding period, insufficient-data
count, and low/medium/high confidence bands. The final evaluation period is not
used to tune thresholds. Deterministic fixtures verify methodology and
reproducibility; they are not advertised as expected live profit.

## MCP contract

Version 1.1 exposes 93 tools: the exact frozen 48-tool Version 1.0 prefix plus
45 additive tools. The additions cover:

- system/provider/catalogue health, recovery, diagnostics, quarantine,
  integrity, updates, and circuit reset;
- selected player, holdings, imports/exports, trade journal, preferences, and
  watchlists;
- GE analysis, scans, buy/sell candidates, explanations, manual order plans,
  portfolio, backtests, and paper trading;
- real-data and market status/refresh, provider disagreements, offline mode,
  and account-aware quest shopping lists.

Inputs are strict, bulk replacement requires explicit confirmation, effects
are classified, and public failures use structured envelopes with trace IDs.
Hosted maintenance operations retain operator authorization and tenant
isolation.

## Desktop changes

The desktop now provides source-aware first run, player/source status, real
skills, selected profile, holdings, cash, portfolio, journal, watchlist, paper
trading, backtest, buy/sell candidate, and item-analysis views. Candidate cards
show recommendation, score, confidence, guide price age, trend, volatility,
volume, buy limit, zones, maximum quantity, reasons, and warnings. There is no
unexplained one-click Buy control. Preview warnings persist across every page.

The Rust integration test crosses the real Tauri command implementation into a
stdio MCP process and temporary SQLite database. It verifies XP calculation,
profile creation/selection, holdings persistence, selected snapshot, and paper
trade persistence across separate MCP processes.

## Remaining limitations

- Public APIs provide snapshots and guide-price history, not a live bank,
  inventory, active-offer feed, complete quest state, or GE order book.
- Alt1 bank and GE-history OCR import is not included in 1.1.0. Users enter or
  import those records manually; visible quest suggestions remain read-only
  until confirmed.
- Live-provider availability and upstream schema changes are outside project
  control; retained cache and health reporting reduce but cannot remove that
  risk.
- Recommendations and backtests are estimates and can be wrong. Public guide
  values do not guarantee a fill.
- Platform signing, Windows code signing, and Apple notarisation require
  maintainer credentials.
- Ollama and LM Studio live smoke checks require those optional local daemons.
