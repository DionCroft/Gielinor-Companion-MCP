# Version 1.0 final report

Validation date: 2026-07-24. This report covers the complete incremental route
from the verified Version 0.1 baseline through the stable Version 1.0 source
release.

## 1. Overall architecture

The monorepo uses inward-pointing boundaries:

```text
shared schemas <- deterministic core <- providers / SQLite
                                   <- stdio MCP / hosted HTTP MCP
                                   <- Tauri bridge / React desktop
shared schemas <- bounded local-model runtime <- Ollama / LM Studio
local guide pack <- consented Alt1 visible-main-chat reader
```

Provider parsing, persistence, transports, UI, and models cannot replace core
calculations. All gameplay interaction remains read-only. See the
[architecture overview](../architecture/overview.md).

## 2. Packages and applications

- `packages/shared-types`: stable Zod domain/tool/profile contracts.
- `packages/core`: XP, profile, quest, levelling, and GE services.
- `packages/providers`: Jagex/Wiki adapters, cache, API v1 registry, routing,
  health, and deduplication.
- `packages/database`: SQLite repositories and migrations 1–5.
- `packages/agent-runtime`: bounded model-independent tool-call runtime.
- `apps/mcp-server`: local stdio MCP server and library.
- `apps/hosted-server`: stateless Streamable HTTP MCP and account isolation.
- `apps/desktop`: Tauri 2/React application and bundled local runtime.
- `apps/alt1-overlay`: optional consented read-only Alt1 guidance.

## 3. Supported clients

Claude Desktop, Claude Code, LM Studio as an MCP host, standards-compliant stdio
MCP clients, standards-compliant Streamable HTTP clients, the standalone
desktop, and supported ChatGPT custom remote-MCP apps. Ollama and LM Studio can
also act as optional loopback model providers inside the desktop.

## 5. Database schema and migrations

SQLite schema 5 is current. Migration 1 creates profiles/provider cache, 2 adds
quests, 3 training methods, 4 GE catalogue/history, and 5 operational indexes.
Migrations are contiguous, forward-only, transactional, and never edit SQL
already shipped under an existing number. Fresh schema-5 and sequential
schema-1-to-5 upgrade tests pass with profile JSON preserved. Portable profile
schema v1 accepts the documented legacy-v0 migration.

## 6. External providers

Public normal/Ironman/Hardcore Hiscores, Jagex ItemDB detail and graph endpoints,
and RuneScape Wiki quest, training, MediaWiki, and GE Market Watch sources.
Every response has a timeout, HTTP check, runtime validation, normalization,
provenance, timestamp, transactional write, and last-valid-record protection.
Provider API v1 preserves explicit priority, fallback, disagreements, offline
eligibility, and health.

## 7. Automatic update behavior

There is no silent or background updater. The app displays its version and
directs users to manually download, verify, close the app, and install an
update. A future updater requires a durable signing key, pinned public key,
rollback tests, and recovery documentation.

## 8. Desktop functionality

First run, multiple profiles, dashboard, skills, quest search/routes/checklists,
levelling plans, GE search/history charts, shopping and valuation, goals,
data-source status, update status, settings, AI providers, profile
import/export, offline retained-data mode, themes, responsive/keyboard
navigation, and about/legal views. All deterministic features work without an
LLM.

## 9. Ollama functionality

The desktop discovers `/api/tags`, verifies tool capability through `/api/show`,
and uses `/api/chat` with bounded multi-turn tool loops. Only unauthenticated
loopback HTTP is accepted. Unsupported models, malformed calls, timeouts, and
provider failures remain explicit.

## 10. LM Studio functionality

LM Studio can launch the stdio MCP server through `mcp.json` or serve as the
desktop's local OpenAI-compatible model endpoint. Model listing and
chat-completions stay on loopback. Version 1.0 stores no LM Studio API token.

## 11. Claude functionality

Claude Desktop uses an absolute local stdio command. Claude Code supports local
stdio, anonymous remote HTTP, and private remote HTTP when the user securely
configures a bearer header. Both receive the same stable 48 tools.

## 12. Hosted MCP functionality

The hosted app provides stateless Streamable HTTP MCP, anonymous public tools,
optional token-authenticated profiles, operator-only refreshes, per-account
SQLite isolation, account export/import/deletion, size/rate/tool/time limits,
Host/Origin/TLS policy, redacted JSON logs, liveness/readiness, container and
reverse-proxy deployment. Local use does not depend on it.

## 13. ChatGPT compatibility and limitations

Current ChatGPT custom apps connect to a public HTTPS remote MCP endpoint, not
the local stdio process. Anonymous public tools are supported where the user's
plan/workspace enables custom MCP apps. Private Gielinor profiles currently use
a fixed bearer header rather than OAuth, so ChatGPT should use the anonymous
surface. Local/private-network endpoints need a supported secure tunnel.

## 15. Live smoke-test results

- Version 0.1: live Hiscores and ItemDB passed.
- Quest source: passed with 380 validated records.
- Training source: passed with 793 methods covering all 29 skills.
- Price sources: both passed with 7,310 items and 180 ordered history points in
  the recorded smoke.
- Ollama discovery returned HTTP 200; the installed embedding-only model was
  correctly rejected as `MODEL_UNAVAILABLE`.
- LM Studio was not running in the verification environment and was recorded as
  unavailable, never as application success.

Live tests remain opt-in because network, rate limit, and upstream outage are
not deterministic CI results. Version 1.0 adds no new RuneScape source.

## 16. Supported operating systems

Windows x64 has locally verified MSI and NSIS installers. GitHub CI compiles and
tests the native application on Windows, macOS, and Linux. The tag workflow
builds macOS DMG and Linux AppImage/DEB where GitHub-hosted platform tooling is
available. Alt1 is Windows-only; every core feature works without it.

## 17. Security controls

Strict validation, timeouts/retries, safe errors, transactional writes,
least-privilege Tauri allowlist/CSP, loopback-only model network scope, hosted
isolation and token digests, request/rate/tool limits, redacted logs, non-root
read-only container, no-new-privileges, dropped capabilities, dependency
audits, checksums, SPDX SBOM, and GitHub attestations. No signing secret is in
source. Platform certificates are optional maintainer inputs.

## 18. Privacy controls

No telemetry, required login, Jagex credential, bank PIN, session cookie, or
cloud model key. Profiles contain public/manual companion data. Local
conversations remain in memory. Hosted logs exclude bodies, tokens, display
names, profile content, paths, and stacks. Alt1 observations stay local and raw
pixels/text are not retained or transmitted. See [`PRIVACY.md`](../../PRIVACY.md).

## 19. Accessibility results

Semantic landmarks, skip link, accessible names, `aria-current`, visible focus,
keyboard-native controls, responsive layouts, reduced motion, non-color status,
themes, and explicit error/loading/offline states passed executable review. All
11 browser journeys passed and screenshots were manually inspected. No critical
blocker was found. Platform Narrator/VoiceOver/Orca sessions remain recommended
for signed mass distribution.

## 20. Known limitations

No instant GE order book, automatic quest-state/bank/inventory discovery, OAuth
private profiles, distributed rate limiter, signed dynamic provider loader, or
silent updater. Platform signing depends on maintainer certificates. Local AI
requires a separately installed tool-capable model. OCR remains advisory and
consent-driven. Full details are in
[known limitations](../roadmap/known-limitations.md).

## 21. Installation commands

```sh
git clone https://github.com/DionCroft/Gielinor-Companion-MCP.git
cd Gielinor-Companion-MCP
corepack enable
corepack pnpm install --frozen-lockfile
corepack pnpm build
```

Run local stdio with `corepack pnpm start:mcp`; run hosted HTTP with
`corepack pnpm start:hosted`. Release archives and installers require checksum
verification. npm registry installation becomes available only after an
explicit registry publication.

## 28. Recommended post-1.0 roadmap

1. Merge the stacked version PRs in order and tag the reviewed main commit.
2. Add OAuth/OIDC for private hosted profiles.
3. Design a signed provider-package trust and revocation policy.
4. Configure maintainer Authenticode/Apple notarization and a signed,
   rollback-capable updater.
5. Add distributed rate limiting and privacy-preserving operations for
   multi-replica hosting.
6. Expand manual Narrator, VoiceOver, Orca, high-contrast, and installer
   usability testing.
